# Работа над ADScan

Перед изменениями прочитай `.project/CONTEXT.md` и `.project/STATE.md`.
Полное исходное ТЗ хранится в `.project/SPEC.md`; последние указания пользователя
имеют приоритет над первоначальным ТЗ и этими заметками.

## Принятые требования пользователя

- Все модели данных используют Pydantic v2, с именованными аргументами при создании.
- README — документация для человека: установка, использование, смысл результата,
  поддержка и ограничения. Архитектура, ход работы, проверки, планы и контекст агента
  хранятся в `.project/`.
- Не добавляй общий `except Exception`, перестраховочные обработки редких ошибок
  и произвольные ограничения обычных пользовательских действий.
- Сохраняй обработку ожидаемых ошибок входных данных: некорректный Python-файл
  не должен прерывать анализ остального проекта; ошибки конфигурации и файлов
  должны быть понятны пользователю.
- Сканирование локальное: не импортировать и не запускать код анализируемого сервиса,
  не обращаться к сети/LLM во время анализа.

## Проверки и рабочие заметки

Зависимости описаны в `pyproject.toml`, зафиксированы в `uv.lock`.
Обычные команды: `uv run pytest`, `uv run ruff check .`,
`uv run ruff format --check .`, `uv run mypy src/adscan`.
В текущей Windows-среде инструменты также доступны напрямую в `.venv/Scripts/`.
Проверяй CLI на `tests/fixtures/fastapi_vulnerable` после изменений основного pipeline.

Обновляй `.project/STATE.md` после завершения изменений: что сделано, чем проверено,
какие ограничения остались. Решения и контекст обновляй в `.project/CONTEXT.md`.
Служебные файлы исключены из сканирования и сборок пакета.
